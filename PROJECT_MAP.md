# Карта проекта

## Стиль разработки

Код компактный, читаемый, без искусственных слоёв и дробления на мелкие модули.
Новую функцию добавляем в подходящий существующий файл; новый скрипт нужен для
самостоятельной роли. Комментарии объясняют причины и неочевидные ограничения.
Короткие выражения не растягиваем на много строк, длинные конструкции не минифицируем.
При изменении структуры или назначения файлов обновляем эту карту.

В `data/raw/<задача>/submission.csv` также публикуется текущий лучший ответ.
Это генерируемый файл, он исключён из git. `viewer.py` читает только известные
JSON внутри выбранных каталогов; по умолчанию это `outputs` и `artifacts/extraction`.
CSV и настройки API ему не нужны. Вкладка «Извлечение» показывает каждый блок
с полями, цитатами и JSON, а также итоговую сборку. Неполный запуск виден уже
после первого сохранённого блока; отсутствие отчёта не считается успехом.

## Связи

Текущий этап: `python -m alfa_agent extract` → четыре sourced-контракта → сверка
с CSV → `ready/failed`; обучение не вызывается. Текущие ограничения и проект
разделения этапов: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Универсальное
извлечение, новая раскладка артефактов, preparation и генерация experiment.py
пока не реализованы; карта выше показывает существующие файлы.
Ниже — сохранённый черновик следующих этапов, который пока не дорабатываем.

- `solution.py` → `runner.run()` → `data.py` + общие контракты / split.
- Сначала `worker.py` выполняет Dummy baseline и появляется первый submission.
- Затем `agents.py` проверяет описание тремя асинхронными Qwen-вызовами.
- Baker предлагает pipeline; worker обучает его; `summarizer.py` вычисляет feedback.
- `runner.py` сохраняет лучшую проверенную ноду и запускает следующую гипотезу.
- `viewer.py` независимо перечитывает эти файлы; он не управляет обучением.

В offline-режиме вместо Qwen используется фиксированная очередь из `runner.py`.
`qwen.py` и `agents.py` — два входа в один API: первый для текстовых диагностических
команд, второй для типизированного асинхронного цикла.

Дерево просмотрщика строится из **реальных `parent_id`**, а не из порядка номеров.
Родитель — лидер на момент запроса гипотезы; параллельные ветви могут иметь одного
родителя. Ошибочные и незавершённые ноды остаются видны. Схема архитектуры во вкладке
«Схема» описана в `architecture()` файла `viewer.py`; обновляем её при изменении flow.
