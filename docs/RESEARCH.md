# Исследователи данных — 25.10.2026

В точке входа платформы включены два фоновых исследователя. Они работают после успешной подготовки данных, параллельно основному поиску. Общий бюджет остаётся 160 минут: 140 на подготовку/поиск и 20 на финализацию. Шесть модельных процессов по одному потоку, общий лимит восьми LLM-запросов, reasoning low и выключенный fallback сохранены.

## Что делает исследователь

1. Получает условие, схему признаков, фиксированные настройки данных/валидации, предыдущие измерения и краткие результаты последних моделей. Выбирает вопрос и до трёх проверок из каталога. Не генерирует исполняемый код.
2. Отдельный процесс читает данные через уже проверенный prepare.py и split.npz. Проверяет хеши подготовки, исходных файлов, плана и split. Для анализа доступны fit с метками, validation без меток и test без меток. Полные исходные строки не передаются в LLM.
3. Вычисляет статистики на воспроизводимой выборке до 5000 строк и до 12 признаков на проверку. Каталог: пропуски/уникальность/дубли/размеры групп/числовые квантили; сдвиг fit/test через KS или total variation; числовые корреляции Spearman; связи с fit-таргетом через Spearman, eta-squared или normalized mutual information в поддерживаемых случаях. Неподдерживаемая проверка отмечается явно, без подмены метрики задачи.
4. Вторая LLM-роль интерпретирует только полученные измерения. Каждое наблюдение содержит ссылки на существующие успешные измерения, предложение эксперимента и ограничения. Несуществующие, failed и unavailable ссылки отвергаются схемой.
5. Новые выводы попадают в контекст планировщика и исполнителя. Планировщик может предложить признаки или другую модель, но полезность проверяется обычным модельным экспериментом на прежнем split. Исполнитель не может использовать исследование как разрешение изменить уже сохранённый план.

Исследователи не переписывают preparation, split, scorer или submission. Они не публикуют отдельного резервного результата. Внешние labels и интернет им не нужны. Артефакты находятся в `research/context.json` и `research/research_NNN/{start,measurements,finish}.json`; сводка включена в report.json.

## Ресурсы и завершение

| Параметр | Значение |
| --- | --- |
| Одновременные исследователи | 2 |
| Всего исследовательских узлов | До 12 |
| Планирование + интерпретация | Обычно 2 LLM-вызова на успешный узел; до 6 с повторами |
| Максимум сетевых попыток исследования | 72, внутри общего счётчика запросов запуска |
| Дедлайн исследовательского узла | До 600 секунд, также ограничен поисковым дедлайном |
| Процесс измерений | До 120 секунд, один поток библиотек |
| Контекст наблюдений | До 12 наблюдений, суммарно до 24 КБ; до 6 открытых вопросов |

Одинаковые измерения не запускаются повторно; порядок выбранных столбцов не делает измерение новым. После трёх подряд неуспешных узлов новые исследования прекращаются, уже активные собираются. При дефиците общего счётчика запросов сохраняется запас для основного поиска. Исчерпание реальной API-квоты по-прежнему останавливает новые вызовы всех ролей — это общий бюджет ключа.

Ошибки API, схемы, процесса, файлов исследования и отмена до входа в корутину изолированы от основного поиска. При завершении поиска исследователи отменяются, дочерние процессы завершаются через существующий process runner, задачи собираются; затем выполняется прежняя финализация. Исследование само по себе не продлевает поиск или финализацию. Два процесса анализа могут временно добавляться к шести модельным процессам; чтение исходных таблиц требует дополнительной памяти, хотя измерения делаются на ограниченной выборке.

Отключение без изменения исходников: `python3 solution.py task.md --research-parallel 0`. Для прямого CLI/Options исследование по умолчанию выключено; submission entry явно включает два процесса. Запуск только baseline (`--max-nodes 1`) пропускает исследование.

## Что взято из Blocks/Pipelines

Сохранён основной цикл: декларативный запрос → измерения в отдельном процессе → интерпретация с доказательствами → общий контекст модельного поиска; два исследователя, общий API gate, изоляция ошибок и очистка при остановке.

Это адаптация к нашей архитектуре, а не копирование всего Blocks. Нет отдельного ожидания начальной EDA-фазы и повторной подготовки split по её результатам. Каталог ограничен описательными измерениями: внутри исследователей не запускаются дополнительные proxy-модели, ablation/feature-рецепты и отдельное дерево обучения. Идеи признаков проверяет основной поиск. В отличие от research_unlimited в Blocks, здесь установлен предел 12 узлов. Это ограничивает расход API и конкуренцию за ресурсы.
