# Подключение к Qwen

Для Qwen используются клиент совместимого API, проверка настроек и команды диагностики.
Команды этого раздела проверяют только подключение. Рабочий ML-прототип запускается
через `solution.py`; схема и команды приведены в корневом README.md.

## Настройки

Локальный `.env` исключён из Git. Для другого участника: скопировать `.env.example`
в `.env` и заполнить собственные доступы команды. Не добавлять ключ в код, Issues или PR.
Переменные окружения имеют приоритет над `.env`.

| Поле | Значение |
| --- | --- |
| `OPENAI_API_KEY` | Токен от организаторов из окружения или локального `.env` |
| `OPENAI_BASE_URL` | `https://changellenge.up.railway.app/v1` для локальных проверок |
| `OPENAI_MODEL` | Необязателен, по умолчанию `qwen/qwen3.8-27b` |
| `QWEN_TIMEOUT_SECONDS` | Таймаут одного API-запроса, по умолчанию 1200 секунд |
| `QWEN_MAX_TOKENS` | Максимум генерируемых токенов, по умолчанию 32 768 |

По инструкции организаторов от 20.10.2026 платформа сама подставляет
`OPENAI_API_KEY` и `OPENAI_BASE_URL`. В коде нет запасного адреса или ключа:
SDK отправляет запросы на `{OPENAI_BASE_URL}/chat/completions`. Прокси подставляет
модель задачи, поэтому отсутствие `OPENAI_MODEL` не мешает запуску.
Из проверяющего контейнера доступен только этот прокси; прямой адрес модели
и собственные сервисы недоступны. Установка пакетов из кода также запрещена.

Ключ вида `sk-…` выдаётся команде организаторами. Дневной общий бюджет — 600 ₽;
после `Budget has been exceeded` нужно дождаться сброса в 03:00 МСК.
Не путать со сбросом лимита сабмитов в 00:00 МСК.
Принимаются HTTP и HTTPS: платформа может передать внутренний HTTP-прокси.
Адрес берётся из окружения без подмены хоста или протокола. Проверяются наличие
хоста, корректность порта и отсутствие логина, пароля, query-параметров и фрагмента.

## Запуск

Из корня проекта, Python 3.12 и uv:

```powershell
uv sync --locked
uv run --locked python -m alfa_agent check-config
```

`check-config` работает без сети и не расходует API-бюджет. Выводит только признаки
наличия настроек. Код завершения 2 означает незаполненные или некорректные настройки.
Даже `ready: true` означает только заполненность настроек, а не успешную авторизацию.

После заполнения ключа:

```powershell
uv run --locked python -m alfa_agent ping
uv run --locked python -m alfa_agent ask --prompt "Кратко предложи схему валидации для несбалансированной классификации."
```

Каждая команда `ping` или `ask` делает один запрос, который может расходовать
командный API-бюджет. Автоматические повторы отключены. В ответе выводятся текст,
модель и статистика токенов, если провайдер её вернул. Денежная стоимость не
рассчитывается: тарифы API организаторов не известны.

Другой файл настроек можно выбрать через `--env-file PATH`. Он не загружается
в глобальное окружение процесса и не переопределяет уже заданные env-переменные.

## Проверки и границы

```powershell
uv run --locked python -m unittest discover -s tests -v
```

Тесты используют HTTP-имитацию, фиктивный ключ и не обращаются к API.
Проверяются адрес и формат запроса, авторизация, лимит генерации, ошибки сервера,
таймаут, отсутствие автоматических повторов и скрытие секрета в диагностике.

Версии прямых зависимостей взяты из requirements организаторов. Файл `uv.lock`
фиксирует локальное окружение этой заготовки; это не замена полному списку
библиотек платформы. Исходный `vendor/baseline.py` сохранён без изменений и
по-прежнему требует отдельного решения вопроса с отсутствующим в списках `mcp`.

## Рабочий путь и результаты проверок

`ping` / `ask` — отдельная текстовая диагностика. Для extraction / preparation /
baseline работают асинхронные роли из `agents.py`: обычный Chat Completions,
JSON-инструкция и локальная проверка контракта. Все роли, включая реализатора,
исправления и Reviewer, используют `reasoning_effort=none` и `chat_template_kwargs.enable_thinking=false`.
`temperature=0`, максимум ответа
32 768 токенов (8192 у Reviewer), таймаут до 300 с; SDK retries отключены, повторами управляет обвязка.
Provider JSON-mode не используется: на новом прокси он давал посторонние поля.
Из content снимается только целая внешняя Markdown-обёртка; поля JSON не удаляются.
Baker получает до 10 запросов на baseline / порцию гипотез; при отклонении —
свежий контекст, последний ответ и конкретную ошибку в начале и конце запроса.
Корректные гипотезы принимаются отдельно; повторяется только отклонённая роль.
После двух одинаковых отказов Baker получает задание сменить направление без
накопленной переписки. История содержит score / статусы, время, источники ошибок
и заменённые блоки pipeline. Отказ модели отмечен model_claim, а не runtime.
Остальным ролям доступен один JSON-repair на ответ. JSON Schema проверяется локально.
Вызовы идут на переданный платформой или локальным окружением `OPENAI_BASE_URL`.

Qwen генерирует `prepare.py` и `experiment.py`; общий Python-контроллер ограничивает
их интерфейс, запускает отдельными процессами и вычисляет score. Поддержка форматов
и кастомных метрик определяется данными, условием и установленными библиотеками.
Схемы extraction не ограничивают их двумя публичными задачами.

Текущий порядок: preparation / ревью → Baker / start → реализация → smoke / ревью → finish
→ Python / delta → две гипотезы. `solution.py` допускает до 100 нод / 10 500 с,
до 1200 с на исполнение; отдельная отладочная CLI-команда оставляет 10 нод / 600 с / 240 с.
После успешного baseline два исполнителя работают без ожидания пары. Baker предлагает
improve лидера и explore другого подхода, видит также pending-планы. В API-записях
node_id связывает запрос с нодой; счётчики исполнителей независимы.
`--max-nodes 1` оставляет один baseline. На реализацию ноды выделяется до 20
API-запросов с учётом Reviewer и JSON-repair. Ошибки smoke / полного запуска и ревью возвращаются
реализатору; сохранённый план не меняется. Пустой код с blocked_reason возвращается
на пересмотр как last_refusal (непроверенное утверждение) в пределах того же бюджета,
без подмены последней ошибки исполнения. Реализатор видит свой start, профиль,
контракт входных DataFrame, общий scorer / writer; родитель — только pipeline / код.
При failed baseline или ошибке его scorer новые гипотезы не создаются,
stop_reason=baseline_failed. Неизвестная метрика не запрещает генерацию предсказаний.
Ошибка кандидата не заменяет лидера.
Start сохраняет план до реализации; заметки и причины отказа попадают в finish.
Команды полного запуска, результаты live-проверок и ограничения приведены в
[README](../README.md) и [архитектуре](ARCHITECTURE.md).

Первая проверка подключения от 19.10.2026 сохранена в
[history/qwen_smoke_test.json](../history/qwen_smoke_test.json). Результаты старых
циклов не описывают текущий runtime. Ключ вводится через `--key-stdin` без записи
в исходники / артефакты и не передаётся окружению дочернего процесса.
