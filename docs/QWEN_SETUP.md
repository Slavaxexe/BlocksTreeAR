# Подключение к Qwen

В проект добавлены клиент совместимого API, проверка настроек и команда короткого запроса.
Команды этого раздела проверяют только подключение. Рабочий ML-прототип запускается
через `solution.py`; схема и команды приведены в корневом README.md.

## Настройки

Локальный `.env` исключён из Git. Для другого участника: скопировать `.env.example`
в `.env` и заполнить собственные доступы команды. Не добавлять ключ в код, Issues или PR.
Переменные окружения имеют приоритет над `.env`.

| Поле | Значение |
| --- | --- |
| `OPENAI_API_KEY` | Токен от организаторов из окружения или локального `.env` |
| `OPENAI_BASE_URL` | `https://inference.airi.net/v1` |
| `OPENAI_MODEL` | `Qwen/Qwen3.8-27B`, имя со страницы модели организаторов |
| `QWEN_TIMEOUT_SECONDS` | Таймаут запроса, по умолчанию 90 секунд |
| `QWEN_MAX_TOKENS` | Максимум генерируемых токенов, по умолчанию 2048 |

На предоставленном скриншоте виден путь `/v1/chat/completions`, совместимый
с интерфейсом исходного baseline. Из примера организаторов получен домен
`https://inference.airi.net`. Полный путь запроса —
`https://inference.airi.net/v1/chat/completions`; SDK добавляет `chat/completions`
к base URL самостоятельно. Пример `/tokenize` использует другой путь сервиса;
он не является endpoint генерации текста.

Строка из трёх частей, разделённых точками, с JWT-заголовком — токен авторизации,
а не адрес сервера. Из неё нельзя достоверно определить домен API.
Ключ не отправляется в сеть, пока base URL и модель не заполнены.
Для удалённого API разрешён HTTPS; HTTP допускается только для localhost.

## Запуск

Из корня проекта, Python 3.12 и uv:

```powershell
uv sync --locked
uv run --locked python -m alfa_agent check-config
```

`check-config` работает без сети и не расходует API-бюджет. Выводит только признаки
наличия настроек. Код завершения 2 означает незаполненные или некорректные настройки.
Даже `ready: true` означает только заполненность настроек, а не успешную авторизацию.

После заполнения ключа:

```powershell
uv run --locked python -m alfa_agent ping
uv run --locked python -m alfa_agent ask --prompt "Кратко предложи схему валидации для несбалансированной классификации."
```

Каждая команда `ping` или `ask` делает один запрос, который может расходовать
командный API-бюджет. Автоматические повторы отключены. В ответе выводятся текст,
модель и статистика токенов, если провайдер её вернул. Денежная стоимость не
рассчитывается: тарифы API организаторов не известны.

Другой файл настроек можно выбрать через `--env-file PATH`. Он не загружается
в глобальное окружение процесса и не переопределяет уже заданные env-переменные.

## Проверки и границы

```powershell
uv run --locked python -m unittest discover -s tests -v
```

Тесты используют HTTP-имитацию, фиктивный ключ и не обращаются к API.
Проверяются адрес и формат запроса, авторизация, лимит генерации, ошибки сервера,
таймаут, отсутствие автоматических повторов и скрытие секрета в диагностике.

Версии прямых зависимостей взяты из requirements организаторов. Файл `uv.lock`
фиксирует локальное окружение этой заготовки; это не замена полному списку
библиотек платформы. Исходный `vendor/baseline.py` сохранён без изменений и
по-прежнему требует отдельного решения вопроса с отсутствующим в списках `mcp`.

## Проверка на реальном сервисе

19.10.2026 отправлен один короткий запрос через `/v1/chat/completions`.
Модель `Qwen/Qwen3.8-27B` ответила «Готов». Сервис вернул статистику:
81 входной токен, 48 выходных, 129 всего; 43 выходных токена отнесены к reasoning.
Результат подтверждает работоспособность текущих настроек и токена на момент
проверки. Срок действия и лимиты токена могут измениться.
Машиночитаемая запись — `qwen_smoke_test.json`; секреты и заголовки авторизации в неё не включены.

Свободный вызов инструментов и исполнение кода LLM не используются. Цикл экспериментов
реализован через типизированные конфигурации; результаты новых проверок см. в README.md.
OpenAI SDK используется как клиент совместимого протокола; запросы направляются
исключительно на явно заданный `OPENAI_BASE_URL`.

## Проверка полного цикла 20.10.2026

Qwen проверен на специально созданных синтетических задачах. В завершённом
прогоне регрессии три extractor и три baker вернули шесть контрактов,
валидных с первой попытки; выполнены четыре эксперимента и обновлён лучший
submission после feedback. API вернул 10 229 токенов суммарного usage.
Временный ключ вводился через скрытый stdin, оставался в памяти процесса
и не записывался в `.env`, артефакты или исходники. Raw API-ответы не сохранялись.

При таймауте API 45 секунд некоторые более ранние вызовы не завершились;
baseline и лучшие предсказания при этом сохранились. Для текущего прототипа
таймаут по умолчанию увеличен до 90 секунд. Usage незавершённых запросов неизвестен.
Structured-output ответы подтверждают совместимость JSON-mode на момент проверки,
но не доказывают серверное enforcement всех JSON Schema. Локальная проверка обязательна.

Live-запуск с локальными условиями был отклонён автоматической проверкой
разрешений на передачу данных внешнему API. Вместо него API проверен на
синтетике; обе настоящие задачи полностью проверены в offline-режиме.
