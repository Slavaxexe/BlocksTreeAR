# Этап 1: условие → проверенный контракт

Текущая задача — извлечь факты из `task.md`, проверить их и остановиться.
Baker, гипотезы, preprocessing, выбор модели, выбор split и обучение сюда не входят.
Ранее написанный полный ML-цикл сохранён отдельным коммитом в ветке `edelkin` как черновой прототип.

## Что извлекаем

Четыре независимых Qwen-вызова получают **только текст условия**, без заранее
определённых target / ID / метрики, без строк CSV и без ответов других extractor’ов.

1. `problem`: тип задачи, имя target; явно указанные единицы и список классов.
   `warnings` сохраняет дословные оговорки о смысле данных и утечках. Пример:
   ID здания не подтверждён как постоянный ключ; бинарный `label` исключён как утечка.
2. `data`: пути train / test / sample_submission, имя ID, путь словаря признаков,
   явно указанная кодировка, разделитель и десятичный знак.
3. `metric`: **основная** метрика и направление оптимизации; дополнительные метрики отдельно.
   Для классификации здесь Macro F1, а Accuracy / Weighted F1 — дополнительные.
4. `output`: путь результата, колонки в нужном порядке, числа или метки классов,
   требование сохранять порядок test и уникальность ID.

У каждого непустого поля есть `evidence[field_name]`: список точных цитат из условия.
Для необязательного неизвестного значения используется `null` или `[]`, без цитаты.
Если критически важный факт отсутствует или противоречив, контракт не принимается.
В первой версии поддерживаются задачи с одним target, CSV UTF-8 / запятая /
десятичная точка, RMSE либо Macro F1 и двухколоночный submission.

Общие ограничения кейса — 8 CPU, 32 GB, 3 часа, доступные библиотеки и запреты —
хранятся в [TASK_BRIEF.md](TASK_BRIEF.md). Они не следуют из каждого `task.md`:
этот режим не выдаёт их за результат извлечения из описания датасета.
Аугментации, алгоритмы, seed и параметры модели являются решениями следующих этапов.

## Пайплайн

```text
task.md
  ├─ ProblemFacts ─┐
  ├─ DataFacts ────┤ четыре асинхронных запроса
  ├─ MetricFacts ──┤
  └─ OutputFacts ──┘
        ↓
Pydantic + проверка цитат, максимум один repair на ответ
        ↓
Extraction: согласованность четырёх блоков
        ↓
Независимая локальная сверка с CSV / шаблоном и основной метрикой
        ↓
ready → extraction.json + task.json
failed → report.json с причиной; принятый контракт не создаётся
```

Для sourced-extractor’ов используется `chat_template_kwargs.enable_thinking=false`.
Поддержка проверена на реальном endpoint отдельным коротким запросом: валидный
JSON, 6 выходных токенов, 0 reasoning tokens. При HTTP 400 выполняется одна
совместимая попытка без JSON-mode / этого дополнительного параметра; локальные
схемы и проверка цитат остаются обязательными. Черновой baker не менялся.

Промежуточные `problem.json`, `data.json`, `metric.json`, `output.json` записываются
по мере успешного завершения соответствующих вызовов. Даже если сборка или сверка
не прошла, уже проверенные блоки доступны для разбора. Сырые ответы API не сохраняются.

Проверки включают:

- строгие типы, отсутствие неизвестных полей, поддерживаемые значения;
- наличие цитаты для каждого заполненного поля и существование цитаты в исходнике;
- буквальное наличие имён файлов, колонок, классов и единиц в их цитатах;
- совместимость task type / metric / prediction type / output columns;
- пути внутри каталога задачи, наличие файлов и словаря;
- target только в train, одинаковые входные столбцы train / test;
- непустые уникальные ID, совпадение ID и порядка test / шаблона;
- совпадение явно перечисленных классов с классами train;
- корректный путь и колонки результата, поддерживаемый CSV-формат.

Проверка цитаты доказывает её наличие в тексте, **не безошибочное понимание смысла**.
Например, различие основной и дополнительной метрики требует отдельной проверки.
Для текущих двух задач ожидаемые факты вручную заданы в тестах и не передаются Qwen.
`local_task()` после извлечения даёт независимую сверку для поддерживаемого формата;
он не является универсальным парсером произвольного задания.

## Запуск

Настройки endpoint / модели — из `.env.example`; ключ можно получить из окружения
либо ввести скрыто с `--key-stdin`, без записи в файл:

```bash
OPENAI_BASE_URL=https://inference.airi.net/v1 OPENAI_MODEL=Qwen/Qwen3.8-27B \
uv run --locked python -m alfa_agent extract \
  --task data/raw/regression/task.local.md --key-stdin
```

Для классификации меняется только путь задачи. По умолчанию создаётся новый каталог
`artifacts/extraction/<задача>/<время>/`; можно указать новый `--output-dir`.
Существующий каталог не перезаписывается. `report.status=ready` и exit code 0
означают принятый контракт; `failed` и exit code 2 — отказ. Нет фиктивного fallback,
который подменяет неудачный ответ Qwen заранее подготовленным правильным JSON.

Проверки без сети:

```bash
uv run --locked python -m unittest discover -s tests -p 'test_extraction.py' -v
```

Тесты пропускают оба настоящих условия через имитированный HTTP API, схемы и
реальные локальные CSV. Отдельно проверяются параллельность, отсутствие подсказок,
поддельные цитаты, выдуманный target, неизвестные поля и отказ при конфликте CSV.
Это проверка кода пайплайна, не доказательство качества реального Qwen.
Usage запроса с таймаутом неизвестен: нули в его записи не означают бесплатный отказ.

## Результаты live-проверки

Проверено 20.10.2026 на реальном `Qwen/Qwen3.8-27B` через API организаторов.
Передавался опубликованный текст соответствующего `task.local.md`; CSV читались
только локально. Значения ожиданий из тестов в запросы не передавались.

- **Регрессия — ready:** `site_eui`, regression, RMSE/minimize; единицы
  `kBtu/ft² за год`; результат `id,site_eui`, числовые значения, исходный порядок,
  уникальные ID. Все четыре блока с первой попытки, 4 вызова, 11 379 токенов usage.
- **Классификация — ready:** `attack_cat`, classification, Macro F1/maximize;
  Accuracy / Weighted F1 отдельно; все 10 классов совпали с train; результат
  `id,attack_cat`, строковые метки, исходный порядок, уникальные ID.
  Для output понадобился один repair: 5 вызовов, 8 884 токена usage.
- Для обоих условий пути, ID, формат CSV, поля задачи / метрик / результата
  совпали с вручную заданными ожиданиями. Все цитаты проверены по исходному тексту.
  `warnings` проверены как дословные оговорки; это не обещание извлечь все нюансы документа.
- До отключения thinking первый прогон регрессии завершился `failed`: metric / output
  прошли, problem / data получили таймаут. Отказ сохранён, готовый контракт не подставлялся.
- Полный набор: **32 теста прошли**, включая 5 тестов этого этапа. Обучение и baker
  во время live-проверок этого этапа не запускались.

Локальные артефакты, исключённые из git:
`artifacts/extraction/regression-stage1-final/` и
`artifacts/extraction/classification-stage1/`. В каждом — четыре sourced-блока,
`extraction.json`, совместимый `task.json` и `report.json`.

Граница доказательства: два известных условия подтверждают этот минимальный контракт
и обработку исправлений / отказов. Это не измерение надёжности на всех возможных
условиях. Неоднозначные метрики, произвольные форматы ответа, несколько target и
сборка общих ограничений из PDF пока не поддерживаются.
