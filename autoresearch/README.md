# AutoResearch: сквозной пайплайн регрессии с памятью

```
task.md ─► 0 ЗАДАЧА ─► 1 АУДИТ ─► 2 ВАЛИДАЦИЯ ─► 3 ПРИЗНАКИ ─► 4 БАЗОВАЯ ЛИНИЯ ─► 5 ЦИКЛ ИССЛЕДОВАНИЯ ─► 6 АНСАМБЛЬ ─► 7 ФИНАЛ
            Qwen: сводка   Qwen: выводы,   код              код: блоки       + страховочный      Qwen ⇄ память ⇄ код        код         submission.csv
            и риски        ключ объекта                     и песочница      submission          (гипотеза→опыт→урок)                    + отчёт
                                       ▲                                                           │
                                       └──────────── ПАМЯТЬ: journal.jsonl + state.json ◄──────────┘
```

Запуск (из корня репозитория):
```bash
uv run --locked python -m autoresearch.run data/regression/task.md              # с Qwen (ключ в .env)
uv run --locked python -m autoresearch.run data/regression/task.md --no-llm     # без Qwen
uv run --locked python solution.py data/regression/task.md                      # как на платформе
```
Флаги: `--budget` (с, по умолчанию 10 800 = 3 ч), `--max-experiments`, `--llm-calls` (лимит вызовов Qwen, по умолчанию 45), `--out`.

## Принципы
1. **Qwen решает, код считает.** Каждое предложение Qwen — проверяемый JSON (или функция признаков). Код проверяет
   и исполняет, метрику считает только код. Числа, на которые ссылается Qwen, берутся из памяти.
2. **Память — единственный источник истины.** Qwen stateless, поэтому перед каждым вызовом получает сжатую память:
   факты аудита, ВСЕ эксперименты (гипотеза, результат, вердикт, её урок), лучшие подробно, выводы, бэклог идей,
   отклонённые предложения и почему. Полная история — в `journal.jsonl` (каждый шаг, каждый сырой ответ Qwen).
3. **Валидация повторяет test.** Если test — следующий период (как здесь: test = год 6), фолды: учимся на прошлых
   периодах, проверяем на следующем. Ранняя остановка — только на части обучающего фолда.
4. **Признаки по таргету — только из прошлого.** История объекта и групп считается строго по более ранним периодам,
   поэтому один и тот же расчёт без утечки годится и для фолдов, и для test.
5. **Пайплайн не стоит из-за LLM.** Нет ключа, квота, сбои, трижды невалидный ответ → эвристический исследователь
   продолжает с того же места памяти. Сразу после базовой линии пишется страховочный submission.
6. **Бюджет.** Каждый эксперимент — подпроцесс с таймаутом; перед запуском оценка времени по фактическим опытам;
   на ансамбль и финал резервируется время по фактической длительности лучших моделей.

## Этапы
| # | Модуль | Что делает | Где Qwen |
|---|---|---|---|
| 0 | `task.py` | файлы, таргет и id (из шаблона ответа), метрика (regex по task.md) | предметная сводка, риски; метрика — только с точной цитатой |
| 1 | `audit.py` | профиль таргета и хвоста, колонка времени (test строго позже train), поиск ключа объекта (жадно, по повторяемости во времени, покрытию test и корреляции с историей), adversarial validation сдвига, группы | выводы по фактам, альтернативные ключи объекта — код их оценивает и берёт лучший |
| 2 | `validation.py` | фолды: rolling-origin по времени / GroupKFold / KFold; ранняя остановка внутри фолда | — (решение кода) |
| 3 | `features.py`, `custom_code.py` | блоки: base, missing, families, entity_history, group_history, oof_target_encoding, log_numeric; код Qwen → проверка AST → песочница → новый блок | пишет функции признаков |
| 4–5 | `research.py`, `experiment.py`, `models.py` | эксперимент = блоки + модель/лосс/параметры + режим обучения; OOF, метрика по фолдам, разрыв train/val, разбор ошибки (хвост, с историей/без, худшие сегменты) | на каждом шаге: вердикт по последнему опыту, урок, новые выводы, бэклог, следующая гипотеза (или стоп) |
| 6 | `ensemble.py` | жадный ансамбль по OOF; принимается, только если лучше лучшей модели ≥ 0.3% | — |
| 7 | `final.py`, `report.py` | переобучение на всех данных, смесь, проверки submission; report.json, leaderboard.csv, SUMMARY.md, dashboard.html | — |

## Что Qwen может предложить в одном шаге
`spec.blocks` (из доступных), `spec.model` (lightgbm/catboost/xgboost/extra_trees/random_forest/ridge/elasticnet,
лосс из реестра `model_selection`, log1p, параметры из белого списка с границами), `spec.training` (веса недавних
периодов, удаление колонок по шаблону, обрезка хвоста y при обучении) и `custom_feature_code`.
Валидатор отклоняет: блок/модель/лосс/параметр вне каталога, значения вне границ, повтор уже проведённого опыта,
опыт, не помещающийся в бюджет, запрещённый код, ранний stop (< 8 опытов), несуществующего родителя.

## Папка запуска
```
artifacts/autoresearch_<время>/
  journal.jsonl        каждый шаг: факты, этапы, вызовы Qwen (сырые ответы, токены, ошибки валидации), эксперименты
  state.json           текущая память (то, из чего собирается промпт)
  folds.npz            фиксированные фолды
  features/*.parquet   блоки признаков (+ custom_N_work/code.py — код Qwen)
  experiments/exp_NNN/ spec.json, result.json, oof.npy
  final/               финальные модели и предсказания
  ensemble.json, report.json, leaderboard.csv, SUMMARY.md, dashboard.html, submission.csv
```
