# Локальная проверка ML-задач

Подготовлены пять наборов из открытых UCI-данных. Это учебный стенд для проверки
переноса одного агента на разные схемы, метрики и способы валидации. Код агента
и исходные public-датасеты при подготовке стенда не менялись.
Каталог задач: [data/practice](../data/practice/README.md).

## Как оценивают организаторы

По [материалам проекта](../Info/task.md), стр. 6 и 16–19 исходного задания:

1. Решение получает task.md, train с таргетом и test без таргета. Каждый кейс
   запускается отдельно, результат — submission.csv.
2. Внутреннюю валидацию решение выделяет из train самостоятельно. В текущем
   агенте make_split генерируется на этапе подготовки; worker сохраняет split
   и сравнивает эксперименты по этой валидации. Его finish.value/best.json —
   локальное качество, не оценка скрытого теста.
3. Платформа сравнивает submission с недоступными решению ответами test.
   Промежуточных оценок этого теста во время решения агенту не дают.
4. Public содержит две известные задачи: RMSE регрессии и Macro F1 классификации.
   Метрики переводятся в баллы относительно бейзлайна организаторов и усредняются.
   Числа B_RMSE/B_F1 не раскрыты; этот стенд не может воспроизвести официальный score.
5. Private — две новые задачи с новыми условиями и данными через тот же интерфейс.
   Типы задач, финальные метрики и содержание заранее не раскрыты.
   Это отдельные задачи, а не подтверждённый второй private-поднабор test каждой public-задачи.

Значит, **внешний test отделяет автор набора/платформа**, а **валидацию внутри
train — само решение**. Здесь внешний test уже отделён и очищен от таргета.
Дополнительные validation.csv не создавались, чтобы проверить выбор split самим агентом.
Для исходных двух public-задач правильные ответы test у нас отсутствуют; их нельзя восстановить
из имеющихся файлов, поэтому локальный оценщик распространяется только на пять новых наборов.

## Что предположительно полезно для private

Подтверждены универсальный интерфейс, две новые задачи и ограничения CPU/RAM,
отсутствие интернета и предобученных моделей. На этой основе разумно тренировать
табличную регрессию, бинарную классификацию, другие классы/таргеты, дисбаланс,
вероятностный ответ и неизвестную метрику. Это предположения, а не сведения о private.

Три обычные табличные задачи ближе всего к опубликованным примерам. Велопрокат
проверяет временной сдвиг, логарифмическую метрику и удаление утечки. SMS проверяет
выбор текстовых признаков без скачивания предобученной модели. Доказательств,
что на private будут временные ряды или NLP, нет. Изображения/аудио не включены:
в опубликованных примерах их нет, а эти пять кейсов запускаются с текущими зависимостями.

## Файлы и граница доступа

```text
data/practice/<dataset>/
  task.md
  train.csv
  test.csv                  Только признаки и id
  data_dictionary.csv
  sample_submission.csv     Заглушка, не правильные ответы
evaluation/private/<dataset>/
  test_labels.csv           Только id и правильный таргет test
  manifest.json             Источники, SHA-256, split, количества строк и классов
evaluation/catalog.py       Контракты задач и описания полей
evaluation/practice.py      Сборка, аудит, экспорт, оценщик, диагностические модели
tmp/practice_sources/       Кэш исходных данных с полными таргетами, вне Git
```

Здесь hidden означает отделение файлов для внешнего оценщика. Это **не изоляция
прав доступа ОС**: процесс с доступом ко всему репозиторию технически может прочитать
evaluation/private и исходный кэш. agent.data.inventory смотрит только внутрь каталога
переданного task.md, поэтому эти ответы штатно не попадают в его список входных файлов.
AST-проверка сгенерированного кода тоже не является файловой песочницей.

Для честного изолированного прогона экспортируйте только разрешённые файлы командой
export, а в контейнер/другого пользователя передавайте только этот каталог и код
solution.py, agent/, schemas/ с зависимостями. Не передавайте evaluation/, исходные
архивы, весь репозиторий или каталог tmp/. Оценщик запускайте снаружи после завершения.
Один export без ограничения прав процесса сам по себе изоляцию не создаёт.
Это открытые датасеты: тест скрыт в рамках локального протокола, а не секретен в интернете.

## Запуск

Все команды ниже выполняются **из корня worktree slava**; Python 3.12 и зависимости
берутся из pyproject.toml/uv.lock. На Windows вместо `uv run python` можно использовать
`.venv\Scripts\python.exe`. Никаких дополнительных библиотек не требуется.

```powershell
# Проверить готовые данные, схемы, разделения и контрольные суммы; без сети и Qwen
uv run python -m evaluation.practice verify

# Новый каталог только с пятью файлами для участника
uv run python -m evaluation.practice export bank_subscription tmp/practice_inputs/bank_subscription

# Обычный локальный запуск агента; вызывает Qwen и требует настройки API
uv run python solution.py tmp/practice_inputs/bank_subscription/task.md --time-budget 600 --max-experiments 5

# После завершения агента: внешняя оценка submission на скрытых ответах
uv run python -m evaluation.practice score bank_subscription tmp/practice_inputs/bank_subscription/submission.csv
```

`score` выводит JSON с именем метрики, направлением, значением, числом строк и
SHA-256 проверенного submission. Неверные столбцы, ID, порядок, дубликаты,
пропуски, бесконечности, недопустимые классы/вероятности и отрицательные
предсказания RMSLE отклоняются. Оценщик не переставляет строки и не исправляет ответ.
Не выбирайте гиперпараметры по этому тесту: после такого выбора он уже не даёт
независимой оценки обобщения.

```powershell
# Пересобрать пять наборов, скачав только отсутствующие исходники UCI
# Перезаписывает перечисленные входные файлы и ответы; seed и SHA источников фиксированы
uv run python -m evaluation.practice build

# Повторить сборку без сети, если исходники уже закэшированы
uv run python -m evaluation.practice build --offline

# Только один набор: --dataset concrete_strength (также доступно для verify и smoke)
uv run python -m evaluation.practice build --dataset concrete_strength --offline

# Тесты оценщика и протокола, без Qwen
uv run python -m unittest tests.test_practice -v

# Простые диагностические модели; output должен быть новым каталогом
uv run python -m evaluation.practice smoke --output tmp/practice_smoke_new
```

Сборка фиксирует SHA-256 загрузок и отказывается молча принимать изменившийся источник.
Тест воспроизводимости пересобирает данные во временную папку и сравнивает байты;
без исходного кэша только этот тест пропускается. Остальные проверки работают с готовыми файлами.
Число строк Bike Sharing измерено в hour.csv: 17379; на странице UCI указан другой
размер. Для SMS используется физический построчный формат архива: 5574 записи,
включая повторы; одинаковые нормализованные тексты не пересекают train/test.

Проверены контрольные суммы, схемы, наличие/отсутствие таргета, уникальность и
порядок ID, покрытие словарями, отсутствие пересечения групп и временное разделение.
