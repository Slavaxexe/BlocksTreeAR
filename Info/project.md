# Структура проекта

Код пишем прямо и читаемо, без лишних слоёв. Комментарии объясняют причины и
неочевидное поведение. При изменении структуры обновляем эту карту и архитектуру.

```text
AlfaHakaton/
├── solution.py             Вход платформы: путь к заданию → baseline и поиск
├── viewer.py               Просмотр сохранённых экспериментов
├── agent/
│   ├── __main__.py         Команды check-config, ping, ask, extract, baseline, search
│   ├── config.py           Настройки окружения и .env
│   ├── qwen.py             Клиент текстовых запросов
│   ├── agents.py           Роли Qwen, включая Baker и планировщика ноды
│   ├── contracts.py        Структуры JSON для обмена между этапами
│   ├── data.py             Список файлов, профиль данных, пути и хеши
│   ├── runner.py           Агенты блоков, исправления, анализ и выбор лидера
│   ├── search.py           Очередь коротких идей и параллельные планировщики нод 2+1
│   ├── assembly.py         Сборка версий модулей, хеши и выполнение цепочки
│   ├── context.py          Компактные JSON-представления для разных ролей
│   ├── worker.py           Подготовка данных, обучение, оценка и предсказания
│   └── storage.py          Чтение и атомарная запись артефактов
├── data/
│   ├── regression/         Данные и описание регрессионной задачи
│   ├── classification/     Данные и описание классификации
│   └── practice/           Пять дополнительных ML-задач с task.md и test без таргета
├── evaluation/             Сборка и внешний оценщик тренировочных задач
│   ├── README.md           Протокол, источники, запуск и результаты диагностики
│   ├── practice.py         build, verify, export, score, smoke; без изменений агента
│   ├── catalog.py          Описания задач и зафиксированные источники UCI
│   └── private/            Ответы test и манифесты; не передавать решению
├── baseline/               Исходный код и зависимости организаторов
├── Info/
│   ├── assignment.pdf      Исходное задание
│   ├── task.md             Требования и ограничения
│   ├── datasets.md         Описание публичных данных
│   ├── sources.json        Источники и контрольные суммы
│   ├── qwen.md             Настройки, запуск и пути к данным
│   ├── architecture.md     Устройство текущего решения
│   └── project.md          Эта карта
├── schemas/                JSON Schema контрактов
├── tests/                  Тесты кода и просмотра артефактов
├── .env.example            Пример настроек без ключа
├── .python-version         Версия Python
├── pyproject.toml          Зависимости проекта
└── uv.lock                 Зафиксированные версии зависимостей
```

`solution.py` → `agent.runner.run()` → извлечение условия → `prepare.py` →
baseline → анализатор → Baker → очередь идей → планировщики нод → агенты блоков →
сборка модулей → метрики и выбор лучшей ноды → анализатор и новые гипотезы.

Каждый запуск пишет собственный каталог в `artifacts/`. Он содержит `extraction.json`,
`preparation.json`, общий `prepare.py`, сохранённый split и `nodes/node_000/`,
`nodes/node_001/`, ... с кодом, планом, результатом и предсказаниями.
`analysis.json` хранит выводы Qwen, `delta.json` — сравнения метрик,
`journal.json` — историю, `best.json` — указатель на лидера. Артефакты не входят в Git.

Корень данных — каталог переданного Markdown, а не текущая рабочая папка.
Данные не копируются в ноды. Готовый файл ответа публикуется рядом с заданием.
Дополнительные наборы и отдельная оценка на скрытых ответах описаны в
[evaluation/README.md](../evaluation/README.md); метрики нод остаются внутренней валидацией.
Поиск ограничен временем, числом нод и API-запросов. В каждой ноде есть
`modules/` со снимками блоков, `assembly.json` с порядком и хешами и тонкий
`experiment.py`, создаваемый сборщиком. Список `write_blocks` задаёт все новые
или изменяемые модули ноды; каждому назначается отдельный агент Qwen. Общий предел —
8 одновременных обращений для всех ролей. `attempts/<block>/` сохраняет до трёх
версий каждого блока; `executions/` — логи запусков сборки. Основной предок — `parent_id`,
источник каждого блока — отдельный `source_node`.
