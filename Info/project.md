# Структура проекта

```text
AlfaHakaton/
├── solution.py             Точка входа: путь к заданию → baseline и поиск
├── viewer.py               Просмотр сохранённых экспериментов
├── agent/
│   ├── __main__.py         CLI: конфигурация, ping, извлечение и поиск
│   ├── config.py           Окружение и локальный .env
│   ├── qwen.py             Клиент текстовых запросов
│   ├── agents.py           Extractor, подготовка, Baker, реализатор и анализатор
│   ├── contracts.py        Проверяемые JSON-контракты
│   ├── data.py             Инвентаризация, профиль, пути и хеши данных
│   ├── runner.py           Очередь 3+1, исправления и выбор лидера
│   ├── assembly.py         Сборка сохранённых версий модулей
│   ├── context.py          Компактный контекст ролей
│   ├── worker.py           Подготовка, обучение, оценка и предсказания
│   └── storage.py          Атомарная запись артефактов
├── schemas/                JSON Schema контрактов
├── tests/                  Тесты агента и просмотрщика
│   └── fixtures/           Тексты заданий для тестов; без датасетов
├── Info/                   Запуск, архитектура и карта проекта
├── README.md               Краткий запуск и состав репозитория
├── requirements.txt        Предоставленный список зависимостей платформы
├── pyproject.toml          Зависимости локального окружения
├── uv.lock                 Зафиксированные версии
├── .env.example            Пример настроек без ключа
└── .python-version         Python 3.12
```

`solution.py` → `agent.runner.run()` → извлечение условия → `prepare.py` →
baseline → анализатор → Baker → планы сборок → четыре параллельные ноды →
сборка модулей → измерение метрик и публикация лучшего результата.

Каждый запуск пишет собственный каталог `artifacts/` с извлечением,
подготовкой, split, модулями, планами, метриками и диагностикой.
`best.json` указывает лидера; лучший submission публикуется рядом с заданием.
Корень входных данных — каталог переданного Markdown.

По умолчанию работают 4 ML-ноды и до 16 одновременных API-запросов.
Временные бюджеты, число экспериментов, API-запросов и версий кода
не ограничены локально; явные параметры могут задать ограничения.
Лимиты внешней платформы остаются действующими.

Данные, материалы организаторов, отдельный тренировочный оценщик и его
ответы, `.venv`, `.env`, временные файлы и ZIP не отслеживаются Git.
Существующие локальные копии сохраняются. Для запуска после клонирования
нужно отдельно получить входные файлы задачи.
