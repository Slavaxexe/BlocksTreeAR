Все сторонние импорты рабочего графа имеют соответствие в исходном списке. `autogluon.core`, `autogluon.common`, `autogluon.features` относятся к зависимостям разрешённого AutoGluon Tabular. Pandas использует разрешённый PyArrow для parquet.

Сборка содержит только собственный Python-код трёх частей и исходный requirements. Сторонние пакеты, wheels, виртуальное окружение, тесты и исходный baseline в неё не включены. В рабочем пути не обнаружено вызовов pip, установки пакетов или скачивания моделей. Baseline импортирует отсутствующий в списке `mcp`, но наш запуск его не использует. Внешние тесты используют `pytest`, также отсутствующий в списке; эти тесты не входят в загрузочную папку.

Для устранения возможности выбрать необеспеченный optional-backend настройки AutoML ограничены: FLAML — `lgbm`, `catboost`, `xgboost`, `extra_tree`, `rf`; AutoGluon — `GBM`, `CAT`, `XGB`, `RF`, `XT`. Все они используют разрешённые библиотеки. Подключение других AutoML-движков с дополнительными зависимостями отклоняется.

Стандартные модули Python (`json`, `pathlib`, `asyncio`, `tempfile` и другие) не требуют строк в requirements. Временные папки для восстановления собственной структуры модулей создаются во время запуска; это не установка зависимостей.

После добавления классификации аудит повторён для самостоятельной сборки: 55 корневых файлов, 50 собственных модулей, все локальные импорты входят в manifest. Новые классификаторы, стратификация, метрики и `compute_sample_weight` используют тот же разрешённый scikit-learn; дополнительных библиотек нет. Оба реальных прогона завершились успешно. Git index, рабочий requirements и requirements сборки имеют исходный SHA256, приведённый выше. Тесты и baseline не входят в загрузочную папку.
