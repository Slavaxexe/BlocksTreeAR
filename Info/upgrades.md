# Признаки, категории, веса и финальное обучение

## Выражения признаков

Старые десять операций остались. Новая операция expression позволяет LLM
составлять собственные векторные формулы, без отдельной реализации каждой фичи.
В columns перечисляются все исходные столбцы формулы; x0, x1 соответствуют их порядку.
Можно также писать col("имя столбца"). Таргеты нельзя включать во входы или переопределять.

```json
{
  "name": "relative_size",
  "operation": "expression",
  "columns": ["area", "rooms"],
  "parameters": {
    "expression": "where(x1 > 0, log1p(abs(x0)) / x1, 0)"
  }
}
```

Другие примеры:

- `x1 - group_mean(x0, x1)` для [group, value]: отклонение от среднего группы.
- `frequency(concat(x0, x1))`: частота совместного значения категорий.
- `where((x0 > 0) and (x1 < 5), x0 * x1, 0)`: условное взаимодействие.
- `sin(x0 * 6.283185 / 24)`: циклический признак часа.
- `concat(lower(x0), "_type")`: строковое преобразование категории.

Доступны арифметика, сравнения, условия, abs/log/log1p/exp/sqrt/sin/cos/tanh,
minimum/maximum/clip/where, isna/fillna, length/lower/contains/concat,
frequency/group_mean/group_std/group_count. Формулы могут ссылаться на уже созданные
признаки; порядок recipes определяет вычисление. Функции со статистикой обучаются
на fit и затем применяются к другим таблицам. EDA kind=feature сравнивает исходные
и новые признаки на одном внутреннем разбиении, заново обучая статистики только
на обучающей части. Это оценка гипотезы, а не гарантия улучшения итоговой модели.
Произвольные импорты, Python-функции и обращения к файлам в выражениях не исполняются.

## История и target encoding

Это доступные операции, а не обязательные стадии. Имена столбцов, ключ объекта,
стратегию валидации и необходимость признаков выбирает LLM. В промптах нет
рекомендации использовать историю для определённой задачи.

`history` принимает `columns` как одиночный или составной ключ. Например:

```json
{
  "name": "previous_value",
  "operation": "history",
  "columns": ["object_type", "size"],
  "parameters": {
    "time_column": "period",
    "value_column": "target",
    "aggregation": "last"
  }
}
```

Это пример интерфейса, а не встроенные имена. Значение может быть таргетом или
обычным числовым признаком. Доступны last, mean, sum, std, min, max, count,
trend (наклон по времени), age (давность последнего периода).
`window` ограничивает число предшествующих различных периодов, `lag` задаёт
отступ от последнего доступного периода (по умолчанию 1), `min_history` —
минимум наблюдений, `max_age` — максимальную давность. Числовые периоды
сохраняют свои единицы; даты переводятся в дни.

Для каждой строки берутся только строки fit со строго меньшим временем.
Своя строка, тот же период, будущие периоды и метки validation/test исключены.
При нескольких строках одного ключа в последнем периоде last возвращает среднее,
а не произвольную последнюю строку. Без истории получается NaN; `fallback=global`
использует общую статистику только более ранних периодов.

`target_encoding` принимает ключ в columns и параметры target, smoothing,
folds, seed, validation=auto/random/group/time, group_column, time_column.
Обучающие строки кодируются вне своего фолда; групповой режим исключает целую
группу. Временной режим использует только прошлые значения, включая prior.
`class_label` позволяет кодировать отдельный класс индикатором вместо числового таргета.

EDA `entities` проверяет предложенные `key_candidates` (список составных ключей),
повторы, неоднозначность ключ/период, пересечение и покрытие историей в compare.
`split_column` задаёт порядок для этого измерения. Метки не требуются, поэтому
оно доступно до фиксации валидации. Совпадения ключей не доказывают идентичность
реальных объектов. EDA `feature` сравнивает рецепты на внутреннем holdout и
возвращает покрытие и отдельные оценки строк с историей и без неё.

Эти рецепты доступны в features → preprocess → fit → predict и в AutoML.features.
При внутреннем подборе параметры признаков пересчитываются только по его train.
Для AutoML с рецептами, весами или групповой/временной валидацией адаптер создаёт
явный внутренний holdout, заново строит рецепты по его train и передаёт готовые
train/tuning_data библиотеке. После выбора замораживаются модель, параметры,
число итераций и веса собственного ансамбля AutoGluon. Выбранные компоненты
переобучаются на всём fit с заново рассчитанными признаками, без нового поиска.
Именно эти компоненты используются и при финальном обучении на полном train.

В этом режиме нужны validation=holdout, bag_folds=stack_levels=0;
внутренний ансамбль FLAML также отключён. Их внутренние фолды не умеют
пересчитывать наши целевые рецепты. Ансамбли сохранённых нод доступны как прежде.
При отсутствии рецептов/весов и групповой/временной политики прежний CV доступен.

## Веса строк и несколько seed

В обычном fit можно указать `row_weights={time_column: "period", half_life: 1}`:
вес уменьшается вдвое за указанное число единиц времени. Даты используют дни,
веса нормируются до среднего 1. Опорная дата берётся только из обучаемых строк.
Выбранная модель должна поддерживать sample_weight; иначе возвращается ошибка.
AutoML.row_weights использует тот же интерфейс; веса рассчитываются отдельно
для внутреннего train и для переобучения на всём fit. Проверочная метрика остаётся
исходной, без искусственного взвешивания validation.

`seeds=[7,11,23]` обучает выбранную конфигурацию с несколькими seed и усредняет
прогнозы; классификация использует вероятности или голосование. Все модели делят
бюджет одной ноды. Подбор параметров выполняется один раз, а при финальном refit
выбранные настройки, веса и seed применяются к полному train. Функция потерь,
число деревьев и остальные гиперпараметры задаются обычными parameters модели.

## Нативные категории

В preprocess задаются encoding=native и native_backend=catboost/lightgbm/xgboost.
В следующем fit используется соответствующая библиотека. Данные остаются DataFrame:
CatBoost получает строки и cat_features; LightGBM/XGBoost получают dtype=category.
Словарь категорий фиксируется по fit, новые категории обрабатываются при transform.
Для XGBoost автоматически задаются enable_categorical=true и tree_method=hist.
scaling и PCA с native не совмещаются. Прежние ordinal/onehot доступны как раньше.

## Подбор весов

В EnsemblePlan задайте optimize_weights=true, method=mean/vote/probabilities.
weight_trials (по умолчанию 64) ограничивает число локальных кандидатов.
Код сравнивает исходные веса, отдельные источники и неотрицательные смеси только
на сохранённых прогнозах общего внутреннего holdout, используя фактический scorer
задачи. LLM и обучение источников не вызываются. Внешняя валидация оценивает
уже выбранные веса. Они сохраняются в weights_full_diagnostics.json и передаются
анализатору как измеренные факты. Meta-прогнозы такой смеси нельзя использовать
для повторного обучения следующего ансамбля на тех же строках.

## Финальный refit

При time-budget от минуты резервируется до 20% общего времени, максимум
--final-refit-seconds (по умолчанию 300 секунд). Остальное время идёт на поиск.
0 отключает refit. После остановки задач поиска выбранная модель обучается на
всех размеченных строках train; test остаётся только входом для предсказаний.
Гиперпараметры и наборы признаков фиксируются по выполненной конфигурации.
Повторного HPO и вызовов LLM нет. FLAML переобучает выбранные нативные модели,
включая внутренний sklearn stack; AutoGluon использует refit_full выбранного
предиктора с остальными размеченными строками через train_data_extra.
Для этого единственная нативная копия обучающих данных AutoGluon остаётся в его
общем кэше. В ноды она не копируется.

Если победил ансамбль, источники переобучаются по одному разу, а веса, gating
и метамодель stacking остаются замороженными. Итог сохраняется в final/submission.csv,
затем записывается в каталог task.md. final/refit.json фиксирует строки и источники.
Валидационный скор эксперимента не выдаётся за новую оценку refit на скрытом test.
Если refit падает или не укладывается в резерв, остаётся сохранённый сабмит поиска.
Старым артефактам AutoML может не хватать новых метаданных для refit; автоматический
путь предназначен для новых запусков.
