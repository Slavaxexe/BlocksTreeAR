# Входы для компонента обучения и валидации регрессии

Компонент получает готовый отчёт предыдущего Qwen: выбранные семейства моделей, EDA, пути к подготовленным данным, целевую переменную, основную метрику и ограничения разбиения. Постановка бизнес-задачи, самостоятельный EDA и создание новых признаков в эту часть не входят.

Шаблоны находятся в `tests/fixtures/training_component/{random,group,time}.json`. Полные входные отчёты с фактическим EDA и данные создаются генератором:

```powershell
.\.venv\Scripts\python.exe tests/fixtures/training_component/generate.py
```

Зависимости и сеть генератору не нужны. По умолчанию результаты записываются в игнорируемый Git каталог `artifacts/training_component_inputs`. Можно передать `--output-dir` и `--seed`; стандартный seed — `20261023`. Каждый `input.json` использует пути относительно своей папки.

| Сценарий | Train / test | Семейства, выбранные предыдущим агентом | Что проверяет |
|---|---:|---|---|
| random | 600 / 200 | Ridge, LightGBM, Random Forest | Нелинейность, взаимодействия, категории и пропуски; общий holdout, RMSE |
| group | 600 / 200 | Ridge, ExtraTrees | 30 обучающих и 10 новых групп; отсутствие пересечения групп при валидации, MAE |
| time | 500 / 150 | Ridge, SGD | Уже подготовленные лаги; хронологическое разбиение, масштабирование внутри train, RMSE |

В `time` проверяется пошаговая регрессия: для каждой строки теста история уже известна и лаги предоставлены предыдущим этапом. Это не прогноз всего горизонта из одной точки; оценку этого сценария нельзя переносить на многошаговый прогноз.

Все ID — строки с ведущими нулями. Компонент должен сохранить их и порядок строк шаблона. Целевая переменная есть только в `train.csv`. Файл `evaluation_labels.csv` — отдельный синтетический oracle **только для тестового стенда**: путь к нему отсутствует в отчёте. Обучение, Qwen, выбор кандидатов и финальное переобучение не должны его читать.

## Ожидаемый цикл компонента

1. Проверить входной контракт, файлы и выбранные семейства. Qwen использует входной EDA, чтобы обосновать размер holdout, внутренний CV/holdout, параметры и регуляризацию. Ограничения `group`/`time` имеют приоритет над свободным выбором разбиения.
2. Обучить только предложенные семейства, подбирать параметры внутри обучающей части. Зафиксировать внешнюю валидацию для сопоставимого выбора победителя. Для `rmse`, `mae`, `mse`, `mape` меньшая оценка лучше, для `r2` — большая.
3. Сохранить оценки экспериментов и причины следующих изменений. Не выбирать результат по oracle или по неразмеченному test.
4. Зарезервировать время на финальное обучение победителя на всех размеченных строках, предсказания и запись CSV. Полное обучение не должно менять уже измеренный validation score на «оценку полного train».
5. Выдать `submission.csv`: `id,prediction`, столько же строк и тот же порядок, что у `sample_submission.csv`, конечные численные предсказания; журнал сравнения, победителя и статус полного переобучения.

Первичная оценка относится к внешней валидации до полного переобучения. Результат на настоящем скрытом тесте известен только платформе. Стенд может после завершения работы компонента отдельно прочитать oracle и вычислить синтетический test score; эта оценка не должна возвращаться в цикл поиска.

Для этого после завершения запуска доступен отдельный скрипт:

```powershell
.\.venv\Scripts\python.exe tests/fixtures/training_component/evaluate_submission.py artifacts/training_component_inputs/random/input.json path/to/submission.csv
```

Он проверяет число строк, конечность предсказаний и точное совпадение строковых ID/порядка, затем считает основную метрику. Он не является частью агента и не вызывается во время поиска. Дополнительно интеграционный стенд должен проверять одинаковый hash внешнего split у всех кандидатов, точное число строк полного переобучения и явный статус fallback при ошибке или исчерпании времени финального обучения.
