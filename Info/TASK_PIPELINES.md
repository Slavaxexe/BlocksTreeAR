# Пайплайны задач

Планировщик и дерево гипотез общие. Qwen выбирает тип задачи, признаки,
модель и параметры готовых операций; Python для эксперимента не генерируется.
Подготовка читает конкретные форматы файлов и записывает результат в формате задания.

| Задача | Эксперимент | Анализ данных |
| --- | --- | --- |
| Бинарная / многоклассовая классификация | `preprocess → fit → predict`, один LabelEncoder | Обычные association / predictive / permutation |
| Несколько числовых таргетов | Те же операции, независимая модель на каждый таргет | `targets`, `task_predictive`, обычный анализ с `target` |
| Несколько категориальных таргетов | Те же операции, отдельные классы и модель каждого таргета | Распределения и зависимости таргетов, совместная оценка |
| Многометочная классификация | Один бинарный столбец на метку, независимые классификаторы | Частоты, совместная встречаемость и число меток; task_predictive |
| Ранжирование | Те же операции с LGBMRanker / XGBRanker / CatBoostRanker; регрессоры дают pointwise scores | `queries`, `task_predictive` с целыми запросами |
| Кластеризация | Те же операции без y: KMeans / MiniBatchKMeans / Birch / GaussianMixture | `clusters`, `task_predictive`, качество / корреляции / сдвиги |
| Прогноз временного ряда | `forecast`: лаги, скользящие средние, регрессор и рекурсивный горизонт | `series`, `task_predictive`, обычные проверки истории и признаков |

## Структура данных

В `preparation.data` указываются `target_columns`, `id_columns` и при необходимости:

- `query_columns`: один или несколько столбцов ключа запроса для ранжирования;
- `time_column`: наблюдаемый период;
- `series_columns`: ключ ряда; пустой список означает один ряд.

Эти поля выбирает Qwen из задания и измерений. Никаких названий конкретного
датасета в исполнителях нет. Разбиение выполняет общий готовый инструмент:
группы запросов для ranking, время для прогноза, подходящее задаче разбиение для остальных случаев.
После фиксации внешнее разбиение не меняется.

Прогнозы содержат отдельные таргеты; ID, переименование столбцов и дополнительные
поля добавляет `write_submission`. Для вероятностей нескольких многоклассовых
таргетов `output.class_columns` задаёт соответствие `таргет → класс → столбец`.
Для бинарных меток используются вероятности класса 1 в столбцах таргетов.

## Метрики и ограничения

Готовые метрики: RMSE/MSE/MAE/R² для нескольких числовых целей;
F1 с заданным усреднением, exact-match accuracy, Hamming loss, бинарные AUC/logloss;
NDCG/MAP по запросам; silhouette / Davies–Bouldin / Calinski–Harabasz, ARI при известных метках.
Другие определения остаются в сгенерированном `score` подготовки.
`metric.parameters` уточняет `top_k`, `gain` NDCG, `average` и `rmse_aggregation`.
По умолчанию NDCG использует линейный gain, RMSE — корень общего среднего квадрата;
другую формулу из задания нужно указать явно.

Лаги считаются по наблюдениям внутри ряда. Требуется одна строка на ряд/период,
запрашиваемые периоды должны идти после истории обучения. При пропусках времени
календарную сетку необходимо подготовить отдельно. Validation и test прогнозируются
независимо от одной истории fit; их скрытые таргеты никогда не читаются.

Для кластеризации нужен метод с `predict` для новых строк. Произвольные номера
кластеров разных моделей не усредняются. Метрика силуэта не определена, если
на проверочной части получился только один кластер.

FLAML и AutoGluon Tabular принимают несколько supervised-таргетов и многометочные
задачи: отдельный поиск на каждую цель, без передачи остальных таргетов в модель.
У них общий бюджет ноды; `target_metrics` уточняет метрики подбора отдельных целей,
основная внешняя метрика остаётся общей. Сохраняются выбранные модели каждого
таргета, финальный refit не повторяет поиск AutoML.

FLAML также принимает ranking (групповой holdout/CV, NDCG/MAP) и нативный прогноз
рядов (`time_column`, `series_columns`, `horizon`, `frequency`). Для рядов доступны
как ML-модели с внутренними лагами FLAML, так и ARIMA/SARIMAX/Holt-Winters.
Отдельные ряды делят общий бюджет; для нового ряда без истории предусмотрено
среднее fit с явной отметкой в диагностике. Будущие внешние признаки нужны
на каждом шаге горизонта, включая промежуток до запрашиваемого test.
AutoGluon TimeSeries отсутствует в предоставленных зависимостях, Tabular не
поддерживает нативные ranking/forecasting/clustering.

Усреднение и голосование работают по столбцам нескольких таргетов,
обучаемые stacking/gating пока требуют один таргет.
Финальный refit воспроизводит выбранные операции на всём train.
