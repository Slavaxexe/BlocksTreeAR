# Полный пайплайн регрессии

Точка входа принадлежит нашей ветке `max_pipeline`. Внешние ветки скачаны в отдельные каталоги и используются без изменения исходников:

1. `../AlfaHakaton-margo`: подготовка, EDA, внешний split, рецепт признаков.
2. `../AlfaHakaton-model-selection`: диагностики, пробные модели, выбор Qwen пар «семейство + лосс + преобразование таргета» с валидатором и резервным выбором правил.
3. Наша часть: параметры обучения, внутренний holdout/CV, аналитик → планировщик → координатор, выбор победителя по целевой метрике, переобучение на всём train и submission.

```powershell
uv run --locked python run_margo_pipeline.py data/regression --margo-root ../AlfaHakaton-margo --model-selection-root ../AlfaHakaton-model-selection --target site_eui --metric rmse --output-dir artifacts/full-regression-run --time-budget 4800 --preparation-timeout 600 --selection-timeout 450 --probe-seconds 90 --probe-max-rows 12000 --probe-folds 2 --trial-timeout 180 --max-trials 10
```

Каталог результата должен быть новым. Подключение Qwen берётся из нашего `.env`; ключи не сохраняются в JSON заданиях. Единый таймер включает все три стадии. Максимум по умолчанию — 80 минут, это предел, а не обязательная длительность: координатор заканчивает раньше при отсутствии новых полезных опытов или достижении лимита экспериментов.

## Передача данных

`preparation/input_manifest.json` задаёт target, ID и целевую метрику. `output_manifest.json` задаёт внешний split и ссылки на готовые таблицы. Этап выбора получает CSV только из outer-fit строк исходного train; внешние validation-метки не участвуют в его probe и выборе моделей. Он выполняет собственную обработку признаков для probe. В дальнейшем обучение использует зафиксированный рецепт Margo с повторным fit внутри обучающих подвыборок.

`model_selection/stage_input.json` — реальный вход среднего этапа; `stage_output.json` — его полный выход. `training_selection.json` переводит идентификаторы реестра в наши шаблоны, сохраняет нативные параметры лосса, преобразование таргета, приоритеты, объяснения и сведения AutoML. Подсказки AutoML сохраняются для анализа; обычные кандидаты среднего этапа не заменяются автоматически AutoML-движками.

Наш handoff проверяет метрику, target, строки, ID и split, затем создаёт `handoff/input.json`. Лосс и преобразование таргета от среднего этапа фиксированы, Qwen обучения выбирает параметры внутри этих решений. При `log1p` прогноз возвращается в исходную шкалу до вычисления метрики и записи результата.

Победитель выбирается по общей внешней валидации. В финале рецепт и выбранная модель обучаются на всём размеченном train. Метки скрытого test неизвестны: его реальный score локально не вычисляется.

## Артефакты

- `pipeline_report.json`: стадии и общий результат;
- `preparation/`: выход Margo;
- `model_selection/`: вход, факты probe, решение и мост к обучению;
- `handoff/`: фиксированный контракт, split, рецепт, происхождение;
- `training/report.json`: реальные эксперименты и победитель;
- `training/final/`: модель после полного обучения;
- `submission.csv`: итоговый файл.

Для просмотра нашей стадии: `python training_viewer.py artifacts/full-regression-run/training --port 8766`.

Ограничение upstream сохранено: Margo строит исходный EDA по полному train до split. Наши probe и fit не получают внешние validation-метки, но уже подготовленный upstream EDA не является полностью независимым от них. Метрика и target в текущей интеграции задаются конфигурацией по условию задачи. Это локальный запуск из трёх checkout; отдельная плоская сборка ZIP для платформы пока не выполнялась.

## Единственный полный прогон 23 октября

Каталог: `artifacts/full-regression-20261023-01`. Процесс завершился с кодом 0 и статусом `completed` за **528,782 с (8 мин 49 с)**.

Margo: 27,140 с, один запрос Qwen, 73 признака, split 42 646 / 10 662. Средний этап: 54,625 с, семь probe-конфигураций на 12 000 outer-fit строках, два запроса Qwen. Первое решение отклонено из-за evidence-ключа вне FACTS, второе принято исходным валидатором. Переданы шесть семейств с реальными функциями потерь.

| Семейство | Лосс | RMSE общей валидации |
|---|---|---:|
| XGBoost | L2 | **44,553342** |
| ExtraTrees | squared_error | 46,322881 |
| LightGBM | Huber | 46,424791 |
| CatBoost | Huber | 49,395084 |
| MLP | L2 | 51,330534 |
| ElasticNet | L2 | 53,914860 |

Зафиксированы восемь попыток: шесть успешных и две неудачные перед восстановлением LightGBM. Наш allowlist ошибочно отвергал нативный параметр LightGBM `alpha`; исправлено во время запуска. Первый план восстановления дополнительно предложил несуществующий `huber_delta`, который валидатор отклонил; следующий план прошёл с исходным `alpha`, сохранённым в selected-model parameters.

После стартовых моделей следующий план Qwen не успел за оставшиеся 41,2 с общего бюджета пары analyst/planner. Поиск завершился с `planning_unavailable`, финальное переобучение выполнено успешно. **После наблюдаемого таймаута** расчёт бюджета изменён: максимум последних задержек вместо медианы смешанных repair/normal вызовов, 180–300 с на пару в пределах остатка поиска и сохранённого резерва финального обучения. Это исправление не проверялось повторным прогоном; дополнительные тесты не запускались по просьбе пользователя.

Выбран `trial_005 / xgboost_l2_base`: 500 деревьев, depth 6, learning_rate 0.05. Финальный рецепт и модель обучены на всех **53 308** размеченных строках; `submission.csv` содержит **22 449** прогнозов. Число 44,553342 относится к общей отложенной валидации до полного обучения, не к скрытому test.

## Самостоятельная папка для платформы

`tools/build_submission_folder.py` объединяет исходники всех трёх частей в плоскую папку `../Кейс+инструкция/max_pipeline_submission` без ZIP. В ней 50 `.py` и неизменённый requirements, без данных, ключей и окружения. Bootstrap восстанавливает собственные пакеты во временном runtime при запуске. `agent/platform_pipeline.py` разбирает task.md через Qwen, запускает цепочку и публикует submission рядом с заданием. Соседние репозитории для выполнения сборки не нужны; они нужны только при новой сборке из исходников.

Самостоятельная сборка проверена одним запуском `python solution.py task.md` из отдельной копии с данными, без .env и без PYTHONPATH исходного репозитория. Реальный API использовал те же OPENAI_* переменные, что передаёт платформа. `artifacts/standalone-regression-20261023-01/acceptance.json`: exit0, completed, 791,719 с, 12 успешных опытов, 0 ошибок обучения, 0 таймаутов ролей. Средний этап после двух отклонённых Qwen-решений использовал предусмотренный rules_fallback. Победитель XGBoost: RMSE 44,67570775; полный refit 53 308 строк, submission 22 449 строк, ID/порядок/колонки и конечность прогнозов проверены. Поиск завершён по max_trials. Исправленный бюджет пары analyst/planner в этом прогоне позволил успешно выполнить следующий раунд.

Подробности сборки, команда запуска и ограничения: `../Кейс+инструкция/max_pipeline_submission_Инструкция.md`. Это локальный Windows-прогон интерфейса, отдельный Docker Linux не запускался.
