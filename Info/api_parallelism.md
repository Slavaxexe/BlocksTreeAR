# Проверка параллельных обращений к Qwen

20 октября 2026 года; общий ключ команды, прокси организаторов, модель
`qwen/qwen3.8-27b`. Проверены короткие запросы с просьбой ответить `OK`,
128 токенов на ответ, без сетевых повторов. В каждой группе запросы стартовали
совместно из одного Python-процесса через asyncio и общий HTTP-клиент.

| Одновременно | Готовые ответы | Ошибки | Время группы, с | Медиана задержки, с |
|---:|---:|---:|---:|---:|
| 1 | 1 | 0 | 3.828 | 3.828 |
| 2 | 2 | 0 | 1.750 | 1.344 |
| 4 | 4 | 0 | 5.157 | 2.977 |
| 8 | 8 | 0 | 1.640 | 1.102 |
| 16 | 16 | 0 | 3.969 | 2.641 |
| 32 | 31 | 1 ошибка соединения | 15.938 | 1.899 |

HTTP 429 не наблюдался. Ошибка соединения не доказывает лимит 32: причиной
могут быть сеть, прокси или backend. Каждая ступень проверена один раз, поэтому
это не длительный нагрузочный тест и не установленная квота провайдера.
Наиболее высокий полностью успешный уровень в этом измерении — 16.
Для начала использовать 8–16; в этой короткой пробе 8 дало лучшую пропускную
способность. Генерация больших Python-модулей может вести себя иначе.

Отчёт: `artifacts/api-parallelism-20261020T193338Z.json`.
63 запроса, 62 готовых ответа, одна ошибка соединения. Поле `cost` API в сумме
составило примерно 0.629; единица валюты в ответе отдельно не указана.
Предварительная одиночная проба с 32 токенами не дала готового текста;
после неё лимит тестового ответа увеличен до 128.

В проекте `--parallel-agents` задаёт число одновременных HTTP-обращений всех
ролей, `--parallel` — число одновременно исполняемых ML-нод. Для 16 обращений
не требуется 16 отдельных OS-процессов. Обучение CPU-моделей — отдельная нагрузка;
увеличивать число ML-нод по результатам коротких API-запросов нельзя.

Результат не отменяет общий бюджет ключа 600 рублей в сутки, правила
организаторов и ограничение платформы в 3 часа.
