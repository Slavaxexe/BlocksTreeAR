# Запуск

Нужен Python 3.12. Из корня проекта:

```powershell
uv sync --locked
```

Скопируйте `.env.example` в `.env` и заполните `OPENAI_API_KEY`.
Переменные окружения имеют приоритет над `.env`.

| Настройка | Значение по умолчанию |
| --- | --- |
| `OPENAI_BASE_URL` | `https://changellenge.up.railway.app/v1` |
| `OPENAI_MODEL` | `qwen/qwen3.8-27b` |
| `QWEN_TIMEOUT_SECONDS` | `0` |
| `QWEN_MAX_TOKENS` | `0` |

`0` отключает отдельный лимит запроса: таймаут ограничен оставшимся временем
прогона, а лимит токенов выбирает сервер. Положительные значения задают собственные
ограничения. Общий лимит времени и числа API-вызовов сохраняется.
Для Challenger нужен выданный организаторами ключ этого прокси; ключ AIRI к нему
не подходит. Локальный `.env` не меняется при обновлении шаблона.

Thinking включён для Baker и анализатора с `reasoning_effort=medium`; для остальных ролей отключён.
Уровень medium задаёт среднюю глубину рассуждений, но не устанавливает жёсткий лимит времени или токенов.
Флаг передаётся серверу в обоих форматах, используемых совместимыми API.
Для генерации кода и ролей с thinking принудительный JSON-режим не используется,
но текстовый ответ всегда проверяется по JSON-схеме.

На один ответ допускается до трёх HTTP-попыток: не более одного сетевого повтора
и двух ответов с нарушением контракта. Пустой или обрезанный ответ генерируется
заново, а не отправляется как JSON для исправления. При обрезании заданный лимит
токенов удваивается для повторной попытки. Каждый запрос расходует общий бюджет.
После временной ошибки API Baker повторяет запрос идей с паузой 5 секунд.
Готовые ноды продолжают работу, а подготовка и split сохраняются. После трёх
неудачных циклов подряд планирование останавливается, лучший результат сохраняется.

Извлечение условия может повторно использовать факты предыдущего запуска:
должны совпасть хеш текста задания и проверка точных цитат по текущей схеме.
Модели, split и результаты обучения при этом не переиспользуются.

Проверка заполненности настроек без запроса к API:

```powershell
uv run --locked python -m agent check-config
```

Запуск baseline и поиска гипотез:

```powershell
uv run --locked python solution.py data/regression/task.local.md
uv run --locked python solution.py data/classification/task.local.md
```

Эти команды обращаются к Qwen и исполняют сгенерированный Python-код.
Вместо сохранения ключа в `.env` можно добавить `--key-stdin`: программа запросит его при запуске.

По умолчанию весь проход ограничен 600 секундами, отдельный процесс — 240 секундами.
Параметры `--time-budget` и `--experiment-timeout` задаются в секундах.
`--output-dir` позволяет выбрать новый каталог для артефактов.

Поиск включает до 10 нод вместе с baseline, 3 параллельные ноды (2 improve и 1 explore),
до 8 одновременных обращений к Qwen и до 80 API-запросов суммарно вместе с исправлениями.
Число агентов не равно числу нод: каждую создаваемую/изменяемую часть пишет отдельный агент.
Например:

```powershell
uv run --locked python solution.py data/regression/task.local.md --max-experiments 10 --parallel 3 --parallel-agents 8 --max-llm-calls 80
```

Только первый baseline, без поиска новых гипотез:

```powershell
uv run --locked python -m agent baseline --task data/regression/task.local.md
```

Qwen анализирует результаты и предлагает следующие гипотезы с выбором родителя.
Нода реализует одну гипотезу. Baker выдаёт короткие идеи в очередь. Планировщики
нод независимо разворачивают их в порядок блоков и интерфейсы новых модулей;
контракты переиспользуемых блоков подставляет Python. Готовый план запускается сразу,
не ожидая остальных планировщиков. Уже baseline создаёт первые блоки. Каждый реализатор получает
план сборки и пишет один блок `run(state) -> dict`; агенты работают параллельно.
Остальные блоки сборщик копирует из сохранённых нод. После готовности всех модулей
он собирает решение и выполняет цепочку по порядку. `experiment.py` создаёт Python.
На каждый блок по умолчанию до пяти версий кода: первая и до четырёх исправлений,
включая ошибки полного запуска. Лимит задаётся через `--max-code-attempts`.
При исправлении кода и повторе некорректного JSON с кодом включается medium thinking;
общие ограничения времени и API-вызовов сохраняются.
Общий предел 8 включает реализаторов, планировщиков нод, Baker, анализаторы и извлечение требований;
он настраивается через `--parallel-agents` отдельно от числа нод `--parallel`.
Очередь идей пополняется параллельно работе нод. Новые анализы учитываются при
следующем запросе; готовые планы запускаются без ожидания остальных планировщиков.
Общий scorer считает качество; контроллер сохраняет лучший ответ по validation.
Код и результаты всех попыток остаются в отдельных папках нод.

## ML-библиотеки и AutoML

Локальные зависимости закреплены по списку организаторов в `baseline/requirements.txt`.
`uv sync --locked` устанавливает в том числе FLAML, AutoGluon, LightAutoML, CatBoost,
LightGBM, XGBoost, PyTorch и библиотеки предобработки. Агент передаёт ролям реальные
версии установленных ML-пакетов; схемы гипотез не ограничивают семейство модели.
Проверка импортов разрешает весь ML-набор из списка организаторов.

AutoML может объединять свою предобработку, внутренний подбор и обучение в одном
блоке. Внутренние разбиения используют только fit; общий validation не меняется.
Рабочий процесс добавляет в `state['preparation']['runtime']` бюджет обучения,
дедлайн по `time.monotonic()`, число CPU/GPU и каталог текущей ноды. На поиск
выделяется 80% доступного времени процесса, остальное остаётся на предсказания и
сохранение результата. При предварительной проверке бюджет также сокращается.

Модельные файлы и кэш разрешены внутри каталога ноды; для каждой попытки нужен
свой подкаталог, который сохраняется до окончания предсказаний. Загрузка весов,
предобученные модели и установка пакетов из сгенерированного кода запрещены.

## Откуда берутся данные

Первый аргумент `solution.py` — путь к Markdown с заданием. Его каталог становится
корнем для относительных путей к данным. Например:

```text
solution.py data/regression/task.local.md
                  ↓
data/regression/train.csv
data/regression/test.csv
```

Имена файлов определяются из условия и инвентаризации каталога.
Контроллер сохраняет абсолютный `task_directory` в `preparation.json`.
Сгенерированный `load_data(task_directory, config)` читает входы через
`task_directory / config['data']['files'][role]`.

Для другой задачи достаточно передать другой Markdown. Папка не обязана называться
`data`, а файлы — `train.csv` и `test.csv`. Во время запуска данные не скачиваются.

Для локальных публичных задач используйте `task.local.md`: в нём пути соответствуют
файлам в той же папке. Оригинальный `task.md` сохранён без изменений.

Итоговый файл ответа записывается рядом с заданием. Артефакты эксперимента находятся
в `artifacts/` и исключены из Git вместе с локальными настройками и логами.

## Другие команды

Только извлечение условия:

```powershell
uv run --locked python -m agent extract --task data/regression/task.local.md
```

Просмотр сохранённых артефактов:

```powershell
uv run --locked python viewer.py
```

Просмотрщик доступен по адресу `http://127.0.0.1:8765` и не вызывает Qwen.
Во вкладке «Эксперименты» выберите ноду: сверху появится порядок её блоков,
источники версий, статусы агентов каждого блока и отметки исправлений. В деталях доступны код блоков, попытки
и выводы анализатора. Пунктир на графе показывает источники модулей выбранной ноды.
