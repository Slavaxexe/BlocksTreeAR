# Запуск AutoML в max

Добавлены встроенные адаптеры FLAML и AutoGluon Tabular. Для поддерживаемой табличной задачи планировщик создаёт FLAML baseline и независимый AutoGluon-кандидат без генерации кода через Qwen. После их результатов продолжается обычный поиск гипотез.

В max сохранены нулевые бюджеты по умолчанию: локального общего дедлайна и ограничения числа нод нет, параллелизм — 4 ноды и 16 API-запросов. Для встроенного AutoML без явно указанного времени процесса используется конечный ориентир 1200 секунд на одно выполнение, чтобы движок завершал подбор и возвращал результат. Он не останавливает весь поиск; жёсткий таймаут ноды задаётся через --experiment-timeout.

Встроенный сценарий рассчитан на один таргет, классификацию/регрессию и известные адаптеру метрики. Для групповых/временных схем и прочих задач сохраняется исходный поиск через агента. LightAutoML остаётся доступным генерируемому коду, но собственного адаптера пока нет.

Из PowerShell в каталоге проекта:

```powershell
uv run --locked python solution.py data/regression/task.local.md --time-budget 600 --experiment-timeout 210 --max-experiments 4 --parallel 2
```

Для классификации замените путь задачи на `data/classification/task.local.md`.

Пример длительного поиска с запасом до ограничения платформы в три часа:

```powershell
uv run --locked python solution.py data/regression/task.local.md --time-budget 10500 --experiment-timeout 1200 --max-experiments 30 --parallel 3
```

Общее время включает обращения к Qwen, подготовку данных и обучение. Максимум нод не гарантирует, что все они успеют выполниться. Каждой ноде выделено 2 CPU, AutoML получает мягкий бюджет памяти 6 ГБ. Это не жёсткая изоляция памяти процесса.

Нужны OPENAI_API_KEY, OPENAI_BASE_URL, OPENAI_MODEL в окружении или локальном `.env`. `.env` исключён из Git. В среде платформы используйте переменные, предоставляемые организаторами.

Результаты находятся в `artifacts/<имя запуска>/`, лучший `submission.csv` публикуется рядом с файлом задачи. В папках нод сохраняются `flaml_full_diagnostics.json` / `autogluon_full_diagnostics.json`, логи обучения и предсказания.

Подбор параметров использует только fit. Общий внешний scorer оценивает все ноды на одном split. Сравнивать значения внутренней метрики FLAML/AutoGluon друг с другом нельзя.

## Результаты первого запуска 21 октября 2026

Эти запуски выполнены в локальной slava до переноса в max; перечисленные ниже артефакты находятся в соседней папке AlfaHakaton-slava и не входят в Git.

Публичная регрессия: fit 42 647 строк, внешняя валидация 10 661 строка, random split с seed 42 и стратификацией по building_class. Оба движка оценены на одном сохранённом split.

| Движок | Выбранная модель | Внешний RMSE | Обучение и предсказания внутри адаптера |
|---|---|---:|---:|
| FLAML | XGBoost | 41.538109 | 167.766 с |
| AutoGluon | WeightedEnsemble_L2 | 42.435942 | 107.250 с |

Бюджеты движков различались: 210 секунд на полное выполнение ноды FLAML и 120 секунд при повторе AutoGluon, включая загрузку данных и вывод. Таблица показывает работоспособность интеграции и результат этого запуска, а не универсальное превосходство FLAML.

FLAML: `artifacts/automl-regression-run01/nodes/node_000/`. AutoGluon: `artifacts/automl-autogluon-retry/nodes/node_001/`. Повтор AutoGluon не делал запросов к Qwen и использовал исходную подготовку и split. В первом запуске AutoGluon не успевал обучить модель в smoke: подготовка занимала больше выделенных 5 секунд. Исправлено: до 20 секунд на этот этап и 20 итераций маленького GBM. После исправления предварительный этап и полное обучение завершились.

Это значение RMSE нельзя напрямую сравнивать с прошлыми запусками на других разбиениях. Классификация в этом запуске не обучалась. Отдельные тесты не запускались.

Основной поиск завершился по общему бюджету 600 секунд, статус ready, лучшая нода node_000. Дополнительная гипотеза LightGBM после автоматического исправления категориальных типов и поведения при коротком бюджете завершилась с RMSE 42.513509. CatBoost-нода была остановлена общим дедлайном. Всего основной запуск сделал 24 обращения к API, включая повторы. Ошибка первой AutoGluon-ноды остаётся в исходной истории; успешный повтор сохранён отдельно, история не переписывалась.
