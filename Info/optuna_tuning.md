# Подбор обычных моделей через Optuna

К стартовому портфелю добавлены LightGBM и CatBoost с подбором параметров через Optuna. Эти кандидаты не используют FLAML, AutoGluon или LightAutoML. Qwen не генерирует код их обучения и не выбирает значения параметров для каждой попытки.

По умолчанию сохраняются стартовые AutoML-кандидаты, затем добавляются обычные модели с Optuna. Число нод ограничивается --max-experiments; если указать только две ноды и оставить AutoML включённым, до новых кандидатов очередь не дойдёт.

Запуск двух обычных моделей без стартовых нод AutoML:

```powershell
uv run --locked python solution.py data/classification/task.local.md --no-automl --max-experiments 2 --time-budget 600 --experiment-timeout 210 --parallel 2
```

Для регрессии заменить путь на data/regression/task.local.md. Флаг --no-tuning исключает Optuna-кандидатов из стартового портфеля. Эти флаги управляют именно стартовым портфелем, а не служат изоляцией импортов для всего генерируемого кода. Нулевые общие бюджеты max сохраняют прежний смысл: отсутствие локального ограничения поиска.

## Разделение данных

Внешние validation и test используются только для предсказаний. Внутри fit выделяются отдельные части:

1. Обучение моделей в попытках Optuna.
2. Внутренняя валидация для выбора параметров и числа итераций.
3. Отдельная калибровочная часть, которую обе окончательные модели не видели при обучении.

После подбора параметры фиксируются, модели переобучаются на объединении первых двух частей. Базовая модель с начальными параметрами обучается отдельно от подобранной.

Калибровочная часть дополнительно делится на A и B. На A подбираются параметры обработки предсказаний; на B выбирается один из уже зафиксированных вариантов, включая исходные предсказания подобранной модели. B не является независимой итоговой оценкой: он используется для выбора варианта. Итоговую оценку даёт только общий внешний scorer.

После выбора обработки модели не переобучаются на калибровочных строках. Это сохраняет независимость данных, на которых были получены настройки обработки, ценой уменьшения числа строк окончательного обучения.

## Обработка предсказаний

- Вес смеси базовой и подобранной моделей выбирается из небольшой фиксированной сетки.
- Вероятности классификации могут калиброваться температурным преобразованием.
- Для бинарной классификации с метриками по меткам может подбираться порог.
- Для многоклассовой задачи бинарный порог не применяется; температурная калибровка сама по себе не меняет argmax.
- При недостатке строк, редких классов или оставшегося времени обработка пропускается с явной причиной.

Все настройки получаются из внутренних отложенных предсказаний. Ни внешние метки, ни предсказания модели на тех же строках, на которых она обучалась, для этого не используются. Смешиваются две конфигурации одного движка; ансамбля результатов разных нод здесь нет.

## Время и воспроизводимость

В общий бюджет ноды входят обучение, подбор, финальные модели, обработка и предсказания. Реальные callbacks обучения проверяют дедлайн и передают промежуточные оценки Optuna. Pruning останавливает неперспективные попытки; это не гарантирует, что в коротком запуске обязательно встретится остановленная попытка.

Начальная конфигурация включена в поиск как базовый кандидат. В артефактах сохраняются параметры, состояния попыток, внутренние размеры разбиений, выбранная обработка и её область обучения. Улучшение внутренней метрики не гарантирует улучшения на внешней валидации.

Поддерживаются предусмотренные метрики, один таргет, табличная регрессия и классификация без временных и групповых ограничений. Для иных случаев сохраняется прежний путь генерации решения агентом.

## Результаты запусков 22 октября 2026

Выполнены реальные запуски локальных задач классификации и регрессии: по две обычные модели, без стартовых AutoML-кандидатов, с общим бюджетом 600 секунд и 210 секундами на ноду. Сравнение исходной конфигурации и итоговых предсказаний выполнено одним scorer на одном сохранённом внешнем разбиении каждой задачи. Это сравнение двух конфигураций нового адаптера, а не оценка прироста относительно прежнего AutoML-портфеля или платформенного скоринга.

| Задача и модель | Исходные параметры | После подбора | Завершено / остановлено pruning |
| --- | ---: | ---: | ---: |
| Регрессия, LightGBM, RMSE ↓ | 43,5215 | 42,0049 | 3 / 9 |
| Регрессия, CatBoost, RMSE ↓ | 47,3767 | 44,9599 | 3 / 9 |
| Классификация, LightGBM, Macro F1 ↑ | 0,6132 | 0,6132 | 5 / 7 |
| Классификация, CatBoost, Macro F1 ↑ | 0,4072 | 0,4991 | 3 / 1 |

В этих четырёх запусках внутренний выбор сохранил предсказания подобранной модели без смешивания и температурной коррекции. В классификации было десять классов: бинарный порог здесь неприменим. Отдельного запуска бинарной задачи не выполняли. Улучшение в таблице связано с подбором моделей, а не с доказанным выигрышем калибровки или ансамбля.

При первом запуске CatBoost на классификации обнаружена и исправлена ошибка: параметр метрики `use_weights=false` нельзя передавать, когда веса вообще не заданы. Теперь он добавляется только при включённых весах классов. Этот кандидат повторно прошёл smoke и полное обучение на сохранённой подготовке без новых запросов Qwen; исходный report.json сохраняет историю первого запуска. Актуальный результат повторения находится в finish.json ноды и общем сравнении.

Артефакты: `artifacts/optuna-regression-20261022-01`, `artifacts/optuna-classification-20261022-01`; итоговая парная оценка — `artifacts/optuna_paired_comparison.json`. Данные и артефакты не добавляются в Git.
