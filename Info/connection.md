# Подключение языковой модели

BlocksTreeAR использует OpenAI-совместимый Chat Completions API. Адрес, ключ и модель задаются в `.env` или переменных окружения.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `OPENAI_BASE_URL` | Адрес API выбранного сервера, обычно с путём `/v1` |
| `OPENAI_API_KEY` | Ключ доступа |
| `OPENAI_MODEL` | Идентификатор модели на сервере |
| `LLM_TIMEOUT_SECONDS` | Таймаут одного запроса; `0` — до общего дедлайна |
| `LLM_MAX_TOKENS` | Максимум выходных токенов; `0` — настройки сервера |
| `LLM_API_PROFILE` | `standard` или `qwen` |
| `LLM_TOOLS_ENABLED` | `true` для function calling, `false` для текстового режима |

Переменные окружения имеют приоритет над файлом. Для совместимости читаются старые `QWEN_TIMEOUT_SECONDS` и `QWEN_MAX_TOKENS`; внутри одного источника приоритет у `LLM_*`.

При запуске на локальном сервере, который принимает произвольный ключ, укажите в `OPENAI_API_KEY` значение, ожидаемое этим сервером. Поддерживаются HTTP и HTTPS.

## Профили API

**standard** — режим по умолчанию. Передаёт модель и сообщения; ограничение выходных токенов добавляется при заданном `LLM_MAX_TOKENS`. Настройки температуры и reasoning определяет сервер. JSON-схема включается в инструкцию, ответ проверяется локально.

**qwen** — профиль для серверов с параметрами `enable_thinking` и `chat_template_kwargs`. Baker, анализатор и исправление конфигураций запрашивают thinking с `reasoning_effort=medium`; остальные роли используют режим без thinking. Температура — `0`.

При `LLM_TOOLS_ENABLED=true` исправляющая роль и анализатор ошибок могут обращаться к встроенному справочнику через function calling. В текстовом режиме справка, подобранная системой заранее, остаётся в контексте.

## Проверка подключения

Проверка конфигурации выполняется локально:

```sh
uv run --no-sync python -m agent check-config
```

Короткий запрос к модели:

```sh
uv run --no-sync python -m agent ping
```

Свой запрос:

```sh
uv run --no-sync python -m agent ask --prompt "Предложи план исследования табличных данных."
```

Для отдельного файла настроек добавьте `--env-file .env.local`. Флаг `--key-stdin` запрашивает ключ в терминале.

## Задания и наблюдение за прогоном

Команды запуска и мониторинга приведены в [README](../README.md). `task.md` задаёт пути к данным, метрику и формат прогноза. Файлы каждого прогона сохраняются в `artifacts/`; запросы и ответы — в `llm/`, события — в `events.jsonl`.
