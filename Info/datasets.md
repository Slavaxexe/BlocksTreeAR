## Регрессия: энергопотребление зданий

Папка: `data/regression/` относительно корня проекта.

| Файл | Строк данных | Столбцов |
| --- | ---: | ---: |
| `train.csv` | 53 308 | 64 |
| `test.csv` | 22 449 | 63 |
| `sample_submission.csv` | 22 449 | 2 |
| `data_dictionary.csv` | 64 | 5 |

Таргет — `site_eui`, годовое удельное энергопотребление в kBtu/ft².
62 входных признака, плюс `id`. Метрика — RMSE на исходной шкале таргета.
Медиана таргета в train — 76,79; минимум — 1,001; максимум — 993,428.

Категориальные признаки включают `State_Factor`, `building_class`, `facility_type`.
Погодные данные относятся к году измерения таргета, а не к неизвестной будущей погоде.
`Year_Factor` — анонимизированный код периода; `year_built` — календарный год.
`id` не подтверждён как постоянный идентификатор здания между годами.

Пропуски в train:

| Признак | Пропусков |
| --- | ---: |
| `year_built` | 1 727 |
| `energy_star_rating` | 22 222 |
| `direction_max_wind_speed` | 26 309 |
| `direction_peak_wind_speed` | 27 038 |
| `max_wind_speed` | 26 309 |
| `days_with_fog` | 32 928 |

Значение `0` в `year_built` также упомянуто в описании как особенность данных;
оно не входит в приведённые выше подсчёты пустых ячеек.
ID уникальны внутри train и test, пересечений ID между ними нет.

## Классификация: типы сетевых атак

Папка: `data/classification/` относительно корня проекта.

| Файл | Строк данных | Столбцов |
| --- | ---: | ---: |
| `train.csv` | 87 670 | 44 |
| `test.csv` | 41 166 | 43 |
| `sample_submission.csv` | 41 166 | 2 |
| `data_dictionary.csv` | 44 | 5 |

Таргет — `attack_cat`, 10 строковых классов. 42 входных признака плюс `id`.
Главная метрика — Macro F1; Accuracy и Weighted F1 справочные.
Категориальные признаки: `proto`, `service`, `state`; `-` означает отсутствие сервиса.
Пустых ячеек pandas в train не обнаружил; это не означает, что все специальные
значения уже нормализованы.

Число примеров в train:

| Класс | Строк |
| --- | ---: |
| Normal | 28 000 |
| Generic | 20 000 |
| Exploits | 16 696 |
| Fuzzers | 9 092 |
| DoS | 6 132 |
| Reconnaissance | 5 245 |
| Analysis | 1 000 |

| Shellcode | 567 |

Согласно оригинальному описанию, test — стратифицированные 50% официального
hold-out split UNSW-NB15. Бинарная колонка `label` удалена как утечка.

**Особенность ID:** ID уникальны внутри каждого файла, но все 41 166 ID test
также встречаются в train. Это наблюдение о значениях ID, а не доказательство
совпадения строк сетевых потоков. Нельзя считать `id` глобальным ключом для
соединения train и test или переносить по нему таргеты.

## Описания задач и локальные пути

В обеих папках сохранены оригинальные `task.md`. В них указаны вложенные пути
`regression/participants/...` и `multiclass/participants/...`, которых нет в
скачанной структуре. Рядом подготовлены `task.local.md`, где убраны только эти
префиксы. Для локального запуска baseline используйте `task.local.md`.
Файл результата по условиям должен появиться рядом с выбранным описанием задачи.

## Что проверено

- Все восемь CSV читаются как UTF-8, с запятой в качестве разделителя.
- Число строк и столбцов соответствует заданию.
- В train присутствует таргет без пропусков, в test его нет.
- Остальные столбцы train совпадают со столбцами test, включая порядок.
- Словари покрывают все столбцы train; схема обоих словарей:
  `feature`, `role`, `dtype`, `unit`, `description_ru`.
- ID заполнены и уникальны внутри train, test и sample_submission.
- ID и их порядок в sample_submission совпадают с test.
- Колонка `label` отсутствует в классификационных данных.
- Синтаксис исходного baseline проверен без выполнения кода.

Проверка целостности данных завершена. Модели не обучались, качество на скрытом
тесте не оценивалось, реквизиты API не проверялись.
